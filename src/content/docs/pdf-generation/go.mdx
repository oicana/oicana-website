## PDF generation in Go, in process

In Go, PDF generation usually means headless Chrome, driven through chromedp or running in a Gotenberg service, or drawing every table and page break yourself with a low-level library. The first adds a browser to your deployment, the second buries the document design in code.

Oicana compiles PDFs in process through a statically linked native library instead. Install with `go get go.oicana.com/oicana`, load a packed template once, and compile documents from JSON:

```go
templateBytes, err := os.ReadFile("invoice-0.1.0.zip")
if err != nil {
	return err
}
template, err := oicana.NewTemplate(templateBytes)
if err != nil {
	return err
}
defer template.Close()

pdf, err := template.ExportPdf(oicana.Inputs{
	JSON: map[string]any{
		"invoice": map[string]any{
			"number":   "2026-001",
			"customer": "Acme GmbH",
			"total":    "€1,190.00",
		},
	},
})
```

A warmed up template produces a typeset PDF in single digit milliseconds, directly in your service.

## Running it in production

Load the template once at startup and share it across handlers. `net/http` serves every request in its own goroutine, and a `Template` is safe for concurrent use. Compilations of the same instance serialize internally, so for more concurrency under heavy load, create several `Template` instances from the same template file.

The module links the native library through cgo, so builds need a C toolchain. `go run go.oicana.com/oicana/cmd/oicana-install` downloads the library for your platform, verifies its checksum, and prints the `CGO_LDFLAGS` that link it into your binary.

The [net/http example project](https://github.com/oicana/oicana-example-go-net-http/) shows a complete service.
