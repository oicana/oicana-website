## PDF generation in Ruby, in process

Ruby apps generating PDFs usually wrap the abandoned wkhtmltopdf through wicked_pdf or PDFKit, drive headless Chrome through Grover, or write every layout as code with Prawn.

Oicana compiles PDFs in process through a native library instead. Install with `bundle add oicana`, load a packed template once, and compile documents from JSON:

```ruby
require "oicana"

template = Oicana::Template.new(File.binread("invoice-0.1.0.zip"))

pdf = template.export_pdf(
  json_inputs: {
    "invoice" => { number: "2026-001", customer: "Acme GmbH", total: "€1,190.00" },
  },
)
```

A warmed up template produces a typeset PDF in single digit milliseconds, directly in your application.

## Running it in production

Create a template once per process and compile per request. A `Template` is safe to use from multiple threads, and Oicana releases the GVL while it compiles, so Puma's other threads keep serving requests in the meantime. Compilations of the same instance serialize internally, so for more concurrency under heavy load, create several `Template` instances from the same template file.

Oicana cannot compile in a process forked after its parent compiled. With forking servers and job runners like Puma in cluster mode or Solid Queue, create templates on first use instead of during boot, so every worker gets its own.

The [Rails example project](https://github.com/oicana/oicana-example-ruby-rails/) shows a complete application.
